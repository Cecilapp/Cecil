## Languages

Configure languages in `cecil.yml`:

```yaml
language: en
languages:
  - code: en       # `xx` or `xx-XX` (required)
    name: English
    locale: en_US  # `language_COUNTRY` (required)
  - code: fr
    name: Français
    locale: fr_FR
    config:        # localized configuration options (fall back to the global ones)
      title: "Mon site"
```

- Only the paths of the other languages are prefixed with their code (`/fr/about/`); use `language: {code: en, prefix: true}` to also prefix the main language (an alias then redirects `/` to `/en/`).
- A language can be disabled with `enabled: false`.
- Any option can be localized under `config`, including menus and permalinks (`pages.paths`); a missing option falls back to the global one:

  ```yaml
  languages:
    - code: fr
      name: Français
      locale: fr_FR
      config:
        menus:
          main:
            - {id: about, name: "À propos"}
        pages:
          paths:
            - section: blog
              path: blogue/:year/:slug
  ```

## Translated Pages

Use suffixed filenames for translations (the code must be a declared language):

```plaintext
pages/about.md     # /about/
pages/about.fr.md  # /fr/about/ (or /fr/a-propos/ with `slug: a-propos`)
```

- A page in another language that is not a translation of an existing page uses the `language` front matter variable instead of a suffix.
- Translations are linked by `langref` (default: the page path without language); set the same `langref` to link pages with different file names.
- Data files can be localized too: `data/authors.fr.yml` is exposed as `site.data.authors` when `site.language` is `fr`.
- Images can be localized: in a translated page body, `![](/images/banner.png)` uses `banner.fr.png` if it exists; in templates, use `asset('images/banner.png', {language: site.language})`.
- Menu entries are matched across languages by their ID (page ID without language prefix).

## Templates

- `site.language` (code), `site.language.name`, `site.language.locale`, `site.language.weight`; another language with `site.language.name('fr')`
- `site.pages` holds the pages of the current language, `site.allpages` the pages of all languages
- `page.translations`: the translated versions of the current page
- `{% include 'partials/languages.html.twig' %}` renders a language switcher
- `hreflang` alternates are generated by `partials/metatags.html.twig`
- Language-specific templates use the language suffix: `layouts/page.html.fr.twig`

## UI Strings Translation

Wrap every UI string of the templates (labels, buttons, "Read more", etc.) with the `trans` tag or filter, rather than hardcoding text or branching on `site.language`:

```twig
{% trans %}Read more{% endtrans %}
{% trans with {'%name%': site.title} %}Welcome to %name%{% endtrans %}
{% trans with {'%count%': 3} %}{0}No posts|{1}One post|]1,Inf[%count% posts{% endtrans %}
{{ 'Search'|trans }}
{% trans into 'fr_FR' %}Hello{% endtrans %}
```

Translation files live in `translations/` at the project root (`layouts.translations.dir`), keyed by the source string:

```plaintext
my-site/
└─ translations/
   ├─ messages.fr.yaml   # or messages.fr_FR.yaml
   └─ messages.de_DE.mo
```

```yaml
# translations/messages.fr.yaml
Read more: Lire la suite
"Welcome to %name%": "Bienvenue sur %name%"
```

- File names follow `messages.<locale>.<ext>`, where `<locale>` is the language `locale` (`fr_FR`) or its code (`fr`).
- Supported formats are YAML (`yml`, `yaml`) and gettext MO (`mo`), defined in `layouts.translations.formats`; `.po` files are **not** loaded (compile them to `.mo`).
- Theme translations (`themes/<theme>/translations/`) are merged with the site ones; site translations win.
- Extract strings from templates with `php cecil.phar util:translations:extract --locale=fr --save` (`--show` to display, `--format=po` for gettext PO, `--theme=<name>` to merge the messages of a theme).
- Translations are cached: the cache is refreshed when a file is updated or removed, but **not when a new file is added**; run `php cecil.phar cache:clear:translations` in that case.

## Date Localization

Localize dates with the Twig `format_date` filter (`none`, `short`, `medium`, `long`, `full`); `format_datetime` and `format_time` are also available:

```twig
{{ page.date|format_date('long') }}
```

With locales other than `en`, these filters require the `intl` PHP extension.

See the [multilingual](https://cecil.app/documentation/content/multilingual/) and [localization](https://cecil.app/documentation/templates/localization/) documentation.
