# Scripts

This folder contains the shell scripts used to build Cecil websites and to publish Cecil releases and documentation.

## Contents

| Script | Description | Used by |
| --- | --- | --- |
| [`cecil-build.sh`](cecil-build.sh) | Builds a Cecil website on a CI/CD platform | Hosting platforms (Netlify, Vercel, etc.) |
| [`bump-scoop.sh`](bump-scoop.sh) | Generates the [Scoop](https://scoop.sh) manifest | [`release.yml`](../.github/workflows/release.yml) workflow |
| [`deploy-release.sh`](deploy-release.sh) | Deploys release files to the website | [`release.yml`](../.github/workflows/release.yml) workflow |
| [`deploy-documentation.sh`](deploy-documentation.sh) | Deploys documentation to the website | [`documentation.yml`](../.github/workflows/documentation.yml) workflow |

### `cecil-build.sh`

Builds a Cecil website, locally or on a CI/CD platform: statichost, GitLab, GitHub Actions, Netlify, Vercel, Cloudflare Pages or Render.

The script:

1. detects the platform and deduces the build context (`production` or `preview`) and the base URL (on GitLab: `environment:url` of the job; on GitHub Actions: build context only; on Cloudflare Pages and Render: preview deployments only, the `baseurl` of the site configuration is used in production)
2. installs PHP and the image optimization tools (Vercel only)
3. checks that PHP 8.3 or higher is available
4. downloads `cecil.phar` (or the standalone binary without PHP) if the `cecil` command is not available, and verifies its checksum
5. installs themes with Composer if a `composer.json` file is present (Composer installer checksum is verified), and stops on failure
6. runs `cecil build` with the computed options

| Variable | Description | Default |
| --- | --- | --- |
| `PHP_VERSION` | PHP version to install (Vercel only) | `8.3` |
| `CECIL_ENV` | Build context (takes precedence over the deduced one) | deduced from the platform, or `preview` |
| `CECIL_VERSION` | Cecil version to download | latest |
| `CECIL_CMD_OPTIONS` | Extra options for the `build` command, separated by spaces (e.g.: `--optimize`) | _empty_ |

Usage:

```bash
curl -sSOL https://raw.githubusercontent.com/Cecilapp/Cecil/main/scripts/cecil-build.sh
bash cecil-build.sh
```

### `bump-scoop.sh`

Generates the Scoop manifest for the release: `cecil.json`, or `cecil-preview.json` for a pre-release. `deploy-release.sh` then publishes it to the website.

| Variable | Description | Default |
| --- | --- | --- |
| `VERSION` | Release version | taken from `GITHUB_REF` |
| `SHA1` | SHA1 hash of `cecil.phar` | computed from `dist/cecil.phar` |
| `PRERELEASE` | `true` for a pre-release | `false` |
| `OUTPUT_DIR` | Output directory of the manifest | `dist/scoop` |

### `deploy-release.sh`

Publishes release files to the [`Cecilapp/website`](https://github.com/Cecilapp/website) repository:

- `cecil.phar` and its `.sha1` file in `static/download/<version>/`
- Scoop manifest in `static/scoop/` (if generated by `bump-scoop.sh`)
- `static/VERSION` file and `cecil.phar` / `cecil.phar.sha1` redirections (stable releases only)

| Variable | Description | Default |
| --- | --- | --- |
| `GITHUB_TOKEN` | Token with write access to the website repository | _required_ |
| `VERSION` | Release version | taken from `GITHUB_REF` |
| `SHA1` | SHA1 hash of `cecil.phar` | computed from `dist/cecil.phar` |
| `PRERELEASE` | `true` for a pre-release | `false` |

### `deploy-documentation.sh`

Copies the [`docs/`](../docs/) folder to the [`Cecilapp/website`](https://github.com/Cecilapp/website) repository:

- `docs/` to `pages/documentation/` (moved or deleted files are removed, the website index pages are kept)
- `docs/api/` to `static/documentation/library/api/`

The target branch is created if it does not exist, so that a pull request on Cecil can be previewed on the website.

| Variable | Description | Default |
| --- | --- | --- |
| `GITHUB_TOKEN` | Token with write access to the website repository | _required_ |
| `TARGET_BRANCH` | Website branch to deploy to | `main` |

> [!NOTE]
> `bump-scoop.sh`, `deploy-release.sh` and `deploy-documentation.sh` are meant to run on GitHub Actions: they rely on `GITHUB_*` environment variables (`GITHUB_ACTOR`, `GITHUB_WORKSPACE`, `GITHUB_RUN_NUMBER`, etc.).
